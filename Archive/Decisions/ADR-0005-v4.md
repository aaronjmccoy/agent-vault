Given     A project note wins over a shared note of the same name, so a project's ADR-0001 silently replaces the shared ADR-0001 even when the two are unrelated. A [[rule]] that vanishes by accident is [[rules-not-landing]].
Decide    How does a project's own decision relate to the shared ones you rely on?

Where A:  Where a project records its own decision, the [[agent]] numbers it in the project's own series with a project prefix, such as SHOP-0001, and it replaces a shared [[adr]] only when it names that [[adr]] in an amends line.
          → shared [[rule|rules]] stay in force unless a project amends one on purpose · project ids look different from shared ones
Where B:  Where a project records its own decision, the [[agent]] numbers it after the shared [[adr|ADRs]], so no id is used twice, and it replaces a shared [[adr]] only when it names that [[adr]] in an amends line.
          → one numbering for everything you read · shared and project numbers must be kept from clashing as both grow
Combines  exclusive
Recommend A: a prefix makes it clear at a glance which [[rule|rules]] belong to the project.

Decision  A
