Given     Instructions written as intentions get recited back by [[agent|agents]] but never change what they do, which is [[rules-not-landing]]. A [[spec]] needs [[requirement|requirements]] that a test can check.
Decide    How is a [[spec]] written, so that you can see each [[requirement]] pass or fail in a test?

Where A:  When writing a [[spec]], the author writes each [[ears|EARS]] [[requirement]] with an ID and puts its 1–3 [[gherkin|Gherkin]] [[scenario|Scenarios]] under it, in the same file.
          → each [[requirement]] sits next to the tests that check it · the file mixes two notations
Where B:  When writing a [[spec]], the author writes each [[ears|EARS]] [[requirement]] with an ID and puts its 1–3 [[gherkin|Gherkin]] [[scenario|Scenarios]] in a separate file, tagged with that ID.
          → each file keeps one notation · two files to keep in step for every change
Combines  exclusive
Recommend A: [[requirement]] and test stay together.

Decision  A
Consequences
- When a [[scenario]] runs, [[test-step|test step]] code executes it, so it is a test, not an example.
- When writing a test, the author traces it to a [[requirement]] ID or a bug ID, so tests stay within the [[spec]] ([[test-sprawl]]).
