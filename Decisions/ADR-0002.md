Given     Instructions written as intentions were recited back by [[agent|agents]] but never changed what they did. A [[spec]] needs [[requirement|requirements]] that can be checked.
Decide    How is a [[spec]] written, so that every [[requirement]] is checked by a test?

Where A:  When writing a [[spec]], the author puts each [[ears|EARS]] [[requirement]] in a [[gherkin|Gherkin]] [[rule|Rule]] line, with an ID and 1–3 [[scenario|Scenarios]] under it.
          → one file per [[spec]] · each [[requirement]] sits next to the tests that check it
Where B:  When writing a [[spec]], the author keeps [[ears|EARS]] [[requirement|requirements]] and [[gherkin|Gherkin]] [[scenario|scenarios]] in separate files, linked by tags.
          → each file stays pure · two files to keep in step for every change
Combines  exclusive
Recommend A: [[requirement]] and test stay together.

Decision  A
Consequences  The [[scenario|scenarios]] run through [[test-step|test step]] code, so they are tests, not examples. Each test traces to a [[requirement]] ID or a bug ID, which keeps tests from growing beyond the [[spec]].
