Given     A [[spec]]'s [[scenario|scenarios]] run as tests through [[test-step|test step]] code. This decides when those tests run, and who sets the pace.
Decide    When do the tests you've written run automatically?

Where A:  When a change is committed, [[ci]] runs the [[test-step|test steps]] of every [[spec]] the change touches.
          → fast feedback on each change · can miss side effects on [[spec|specs]] it didn't touch
Where B:  When a change is committed, [[ci]] runs every [[test-step|test step]].
          → catches everything · gets slower as tests grow
Where C:  When a release is prepared, [[ci]] runs every [[test-step|test step]].
          → daily work never waits · problems surface late
Where D:  Where a project specifies a test pace, [[ci]] runs that project's tests automatically at that pace, and the project sets the pace at which to [[autocommit]].
          → each project chooses what fits it · there is no shared default
Combines  exclusive
Recommend D: projects differ too much for one pace.

Decision  D
