Given     A project's own [[rule|rules]] and [[term|terms]] sit on top of the shared vault, and where that layer lives decides which sessions read it. It serves [[rules-not-landing]]: a project's own [[rule|rules]] need a home its [[agent|agents]] load.
Decide    Where does a project's own layer live?

Where A:  Where a project has its own [[rule|rules]] or [[term|terms]], the [[agent]] keeps them in a vault folder at the root of that project's repository, layered over the shared vault, so a project [[term]] wins over a shared one of the same name and a project decision replaces a shared one only when its amends line names it.
          → the project layer travels with its code, to collaborators and pull requests · each repository gains a vault folder
Where B:  Where a project has its own [[rule|rules]] or [[term|terms]], the [[agent]] keeps them in a folder named for that project inside the shared vault, layered over the shared vault, so a project [[term]] wins over a shared one of the same name and a project decision replaces a shared one only when its amends line names it.
          → everything stays in one vault on this machine · the project layer does not travel with the code
Combines  exclusive
Recommend A: a project owns its layer, so the layer lives with the project's code.

Decision  A

Consequences
- Where a project has its own layer, it holds the project's [[rule|rules]] and [[term|terms]] only, and its docs and [[job|jobs]] live elsewhere in the repository ([[ADR-0005-v2]]).
- When a session starts in any folder of a repository, the base prompt reads the vault folder at that repository's root ([[ADR-0005-v3]]).
- Where a project records its own decision, the [[agent]] numbers it in the project's own series with a project prefix, such as SHOP-0001 ([[ADR-0005-v4]]).
