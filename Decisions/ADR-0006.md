Given     A [[spec]]'s [[scenario|scenarios]] run as tests through [[step]] code. This decides when those tests run.
Decide    When should the tests you've written run automatically?

Where A:  When a change is committed, [[ci]] shall run the [[step|steps]] of every [[spec]] the change touches.
          → fast feedback on each change · can miss side effects on [[spec|specs]] it didn't touch
Where B:  When a change is committed, [[ci]] shall run every [[step]].
          → catches everything · gets slower as tests grow
Where C:  When a release is prepared, [[ci]] shall run every [[step]].
          → daily work never waits · problems surface late
Combines  A and C combine: touched [[spec|specs]] on every commit, everything before a release.
Recommend A: fast on every change; add C if gaps show up.

Decision  Other
Other     The [[ci]] shall run a project's tests automatically at the pace that project specifies.
Request   Each project will specify a pace by which to [[autocommit]].
