Given     A [[response|reply]] checked only after it is shown stays broken on screen, and a notice about it fixes nothing on its own, which is [[rules-not-landing]]. The reply check can read a [[response|reply]] before it enters the chat.
Decide    What happens to a [[response|reply]] that breaks the reply [[rule]] before you see it?

Where A:  When a [[response|reply]] breaks the reply [[rule]], the reply check holds it back before it enters the chat, and the [[agent]] recomposes the whole [[response|reply]] from the problems found, so only the corrected [[response|reply]] is shown.
          → you only ever see replies that pass · each broken [[response|reply]] costs one more model call, and the [[response|reply]] appears at once instead of streaming
Where B:  When a [[response|reply]] breaks the reply [[rule]], the reply check holds it back before it enters the chat, adds any missing [[term]] [[link|links]] itself, and the [[agent]] recomposes the [[response|reply]] only if other problems remain, so only the corrected [[response|reply]] is shown.
          → missing [[link|links]] are fixed with no extra model call · a [[link]] added mechanically can land on a word used in a plain sense
Combines  exclusive
Recommend A: one way to fix every problem, and the [[agent]] keeps control of its own wording.

Consequences
- If the recomposed [[response|reply]] still breaks the reply [[rule]], the reply check shows it with a notice saying what is wrong.

Decision  A
